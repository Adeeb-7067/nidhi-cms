SECTION 1 — ARCHITECTURE OVERVIEW
────────────────────────────────────────────────────────────────────────────────

DESIGN PRINCIPLE — TWO INDEPENDENT LAYERS

  The system separates two concerns that must not be conflated:

  Layer A — Work Session Integrity (attendance)
    • Tracks whether an employee is "on the clock".
    • Runs whenever sessionId > 0 in Electron, even if screenshot consent
      has not been granted or monitoring is disabled by admin.
    • Heartbeat (60 s), network watchdog (2 min), power events, quit
      handlers, and backend stale-session jobs all belong here.

  Layer B — Screenshot Capture (monitoring)
    • Captures and uploads desktop screenshots on an admin-configured interval.
    • Runs ONLY when ALL of: clocked in + monitoring enabled + consent current.
    • Never runs in the web browser — Electron main process only.

  This split prevents the classic bug where screenshots stop (process dead,
  sleep, network loss) but the attendance record still shows "clocked in".

COMPONENTS AND THEIR RESPONSIBILITIES

  Frontend (React)
  ├── AuthContext            Token management, login, logout, impersonation.
  │                          Clocks out session before clearing tokens on
  │                          logout. stopImpersonation() clocks out the
  │                          impersonated employee before restoring the
  │                          admin session.
  ├── WorkSessionProvider    Single source of truth for session state.
  │                          Syncs sessionId + screenshot config to Electron
  │                          via IPC (cms:screenshot-config). Polls monitoring
  │                          status every 60 s (fallback when Socket.IO down).
  │                          Listens for cms:session-ended from main process
  │                          and invalidates active-session cache + toast.
  ├── ClockInButton          Navbar button (monitorable staff only); shows
  │                          elapsed timer while clocked in.
  ├── ConsentDialog          Bottom-right notification card (Electron only;
  │                          monitorable staff only); non-blocking.
  │                          Declined state persists for the session via
  │                          sessionStorage so the card does not reappear
  │                          on navigation.
  └── RealtimeContext        Socket.io: session_terminated (admin force-end),
                             monitoring:config-updated (live config push).

  Electron (main process) — owns all reliability-critical session logic
  ├── main.js
  │   ├── Screenshot scheduler     desktopCapturer + upload (Layer B).
  │   ├── Session monitoring       Heartbeat, network watchdog, power
  │   │                              events, main-process clock-out (Layer A).
  │   ├── clockOutFromMain()       Direct API call with token from
  │   │                              localStorage — does NOT depend on renderer
  │   │                              IPC (required for shutdown/sleep/quit).
  │   ├── initiateGracefulQuit()   Clock-out then app.quit(); used by ✕,
  │   │                              tray Quit, before-quit, and auto-update.
  │   └── powerMonitor             suspend → system_sleep; shutdown →
  │                                  system_shutdown.
  └── preload.js             contextBridge API exposed as window.electron.
                             Includes onSessionEnded, setScreenshotConfig,
                             pauseScreenshotMonitoring (future tray pause).

  Backend (Express + MongoDB)
  ├── work-sessions.*        Clock-in/out, heartbeat, active session query,
  │                          session history, force-terminate (super_admin).
  ├── screenshots.*          Upload (magic-byte validation), list, delete
  │                          (admin only), bulk-delete, authenticated proxy.
  ├── monitoring.*           Monitoring status, consent CRUD with GDPR history.
  └── screenshot-purge-job   Two schedules:
                             • Every 24 h: purge expired screenshots (batch
                               200) + close sessions open > 24 h.
                             • Every 2 min: close sessions with no heartbeat
                               > 3 min (client_disconnected).

DATA FLOW (clocked-in Electron session)

  WorkSessionProvider
       │  setScreenshotConfig({ sessionId, enabled, intervalMs, apiBaseUrl })
       ▼
  main.js (cms:screenshot-config)
       ├── sessionId > 0  → startHeartbeat (60 s) + startNetworkMonitor (30 s check)
       ├── enabled=true   → startScreenshotScheduler (intervalMs)
       └── enabled=false  → stop screenshots only; heartbeat continues

  Heartbeat:  POST /api/work-sessions/heartbeat  → updates lastHeartbeatAt
  Screenshot: POST /api/screenshots               → associates sessionId
  Clock-out:  POST /api/work-sessions/clock-out   → main process OR renderer

DATABASES / MODELS

  WorkSession          id, userId, startedAt, endedAt, isActive,
                       deviceInfo, lastHeartbeatAt,
                       stopReason ∈ {
                         clock_out | app_quit | logout |
                         session_expired | admin_terminated |
                         system_sleep | system_shutdown |
                         network_lost | client_disconnected
                       },
                       timestamps.
                       INDEX: unique partial {userId: 1} WHERE isActive=true
                       — prevents two simultaneous sessions at the DB level.

  EmployeeScreenshot   id, userId, sessionId (nullable FK), projectId
                       (nullable FK), fileUrl (raw S3/local URL — never
                       returned to clients), fileSize, takenAt.
                       INDEXES: {userId,takenAt}, {projectId,takenAt desc}

  MonitoringConsent    id, userId (unique), consentGivenAt, consentVersion,
                       ipAddress, userAgent, history[] — append-only array
                       of past consent events for GDPR Article 7 compliance.

  CompanySettings      screenshotEnabled, screenshotIntervalMinutes,
                       screenshotRetentionDays, screenshotBlurEnabled,
                       screenshotConsentVersion. Singleton document.
                       Cached in-process for 60 s; busted on admin save.

TIMING CONSTANTS (reference)

  Heartbeat interval (Electron)           60 s
  Heartbeat stale threshold (backend)     3 min  → stopReason: client_disconnected
  Network timeout (Electron)              2 min  → stopReason: network_lost
  Network check interval (Electron)       30 s
  Clock-out API timeout (Electron main)   5 s
  Idle skip threshold (screenshots)       5 min  (powerMonitor.getSystemIdleTime)
  Monitoring config poll (frontend)       60 s   (when Socket.IO disconnected)
  Active sessions poll (Attendance)       30 s
  Long-abandoned session cleanup          24 h   → stopReason: session_expired
  Screenshot retention                    admin-configured (default 30 days)

SECTION 3 — SUPER ADMIN WORKFLOWS
────────────────────────────────────────────────────────────────────────────────

3.1  ENABLE SCREENSHOT MONITORING

  1. Log in as super_admin.
  2. Settings → Monitoring tab.
  3. Toggle "Screenshot Monitoring" ON.
  4. Set:
       Interval    — capture frequency in minutes (1–60, e.g. 10).
       Retention   — days before auto-deletion (e.g. 30).
       Blur        — when ON, screenshots taken while WhatsApp, personal mail,
                     Telegram, etc. are in the foreground are fully blurred;
                     work apps (IDE, CMS, Jira, …) stay normal. See §4.3.1.
       Consent Version — bump this string (e.g. "v2") whenever the policy
                         changes to force all employees to re-consent.
  5. Save. The in-process cache is busted immediately. Running Electron
     clients pick up the change within 60 s (polling interval) or instantly
     via Socket.IO monitoring:config-updated when connected.

3.2  REVIEW SCREENSHOTS

  Sidebar → Monitor → Screenshots
  • Opens on today's date showing all employees.
  • Each employee row displays 1-hour timeline blocks.
  • Click any block → slide viewer (← / → keys, thumbnail filmstrip).
  • Employee filter dropdown to narrow to one person.
  • Date navigator (← / →) to browse past days.
  • Delete individual screenshots or use trash icon in slide viewer.
    Only admins and super admins can delete screenshots — employees
    cannot delete their own.

  IMPORTANT — Screenshot URL Security:
  Screenshot images are never served directly from S3 or the /uploads/
  folder. The API returns a short-lived authenticated proxy URL:

    https://your-backend.com/api/screenshots/{id}/content?token=<bearer>

  The token embedded in the URL is the same bearer token the requesting
  admin already holds. Images are streamed through the backend, which
  verifies auth and ownership on every request. S3 objects for screenshots
  are uploaded with ACL: private — they are inaccessible via the direct
  S3 URL even if someone discovers it.

3.3  MONITOR ATTENDANCE & ACTIVE SESSIONS

  Sidebar → Monitor → Attendance
  • "Currently clocked in" panel — live list with elapsed time (refreshes
    every 30 s).
  • Sessions tab — full history across all employees; filters by employee,
    shows stopReason column so you can see WHY each session ended.
  • Consent Audit tab — every employee's consent record: version, timestamp,
    IP address, user agent, AND full history of prior consents.

  Stop-reason labels in Attendance UI:
    clock_out           Clocked out (manual)
    app_quit            App quit
    logout              Logged out
    session_expired     Expired (> 24 h abandoned)
    admin_terminated    Force ended
    system_sleep        PC sleep
    system_shutdown     PC shutdown
    network_lost        Network lost (2+ min)
    client_disconnected Disconnected (no heartbeat 3+ min)

3.4  FORCE-TERMINATE A SESSION

  When an account is suspected compromised or an employee leaves
  mid-session without clocking out:

  POST /api/work-sessions/:sessionId/terminate   (super_admin only)

  • Sets isActive = false, endedAt = now, stopReason = "admin_terminated".
  • Emits session_terminated via Socket.IO to the affected user.
  • Employee's Electron client stops screenshots + heartbeat immediately
    on socket event; otherwise within 60 s (monitoring poll).

3.5  CONSENT VERSION UPDATE (policy change)

  1. Change screenshotConsentVersion in Settings → Monitoring.
  2. All employees who consented to the old version will see the "Policy
     updated" badge on the consent banner the next time they open the
     desktop app.
  3. Screenshots stop until they re-consent and clock in.
  4. Each re-consent is appended to the history[] array in MonitoringConsent
     (GDPR Article 7 — full audit trail is preserved, never overwritten).

3.6  CONSENT HISTORY (GDPR)

  The Consent Audit tab shows both the current consent and all prior
  consent events in the history[] array. This satisfies GDPR Article 7
  (demonstrable consent) and Article 5(2) (accountability).

3.7  ABANDONED / STALE SESSIONS (three-tier cleanup)

  Tier 1 — Electron auto clock-out (immediate, best-effort)
    Sleep, shutdown, app quit, network loss → main process calls clock-out
    API before clearing local state. May fail if OS kills the process first.

  Tier 2 — Heartbeat stale job (every 2 min, 3 min threshold)
    If lastHeartbeatAt is older than 3 minutes (or null and startedAt > 3 min),
    backend sets isActive = false, stopReason = "client_disconnected".
    Catches: Task Manager kill, crash, power loss, failed shutdown clock-out.

  Tier 3 — Long-abandoned job (every 24 h, 24 h threshold)
    Sessions still open after 24 hours → stopReason = "session_expired".
    Safety net for edge cases Tier 1 and 2 missed.

SECTION 4 — MONITORABLE STAFF WORKFLOWS (Electron)
────────────────────────────────────────────────────────────────────────────────

4.1  FIRST-TIME CONSENT (Electron only)

  When an admin enables monitoring, a consent notification card appears in
  the bottom-right corner of the desktop app. It does NOT block usage.
  • "Allow monitoring" — records consent with the current policy version;
    screenshots will start on next clock-in.
  • "Decline" (or X) — hides the card for the session; screenshots will
    NOT be taken until consent is recorded.
  • The declined state is stored in sessionStorage so the card does not
    reappear while the same app session is open (disappears after restart).
  • The card reappears if the admin bumps the Consent Version (policy change).
  • Consent is NOT required on the web — screenshots never run in a browser.
  • Clock-in and heartbeat still work without consent; only screenshots are gated.

4.2  CLOCK IN

  • Click the green "Clock In" button in the top navigation bar.
  • POST /api/work-sessions/clock-in — sets lastHeartbeatAt = now.
  • Only ONE active session per user (unique partial index). clockIn() closes
    any lingering active session first.
  • Button turns red and shows elapsed time.
  • WorkSessionProvider sends sessionId to Electron main process.
  • Heartbeat + network monitor start immediately (Layer A).
  • If monitoring enabled AND consent current → screenshot scheduler starts
    (Layer B).

4.3  WORKING — SCREENSHOT CAPTURE

  IMMEDIATE CAPTURE ON SESSION START
  When monitoring transitions from off → on, one screenshot is captured
  immediately before the first interval tick.

  Example (10-minute interval):
    10:00  Clock In → immediate screenshot (if consent + monitoring on)
    10:10  Interval screenshot
    10:20  Interval screenshot
    ...

  ONGOING CAPTURES
  • Captured in Electron main process (desktopCapturer) — never in browser.
  • PNG/JPEG magic-byte validation on server; other payloads → HTTP 400.
  • sessionId verified server-side against uploading user.
  • Idle ≥ 5 min → scheduled capture skipped (immediate t=0 capture exempt).
  • 3-attempt upload retry (1 s, 2 s backoff); aborts if window destroyed.
  • Successful upload resets network watchdog (recordApiContact).
  • Tray tooltip: "CMS Desktop · Screen monitoring active".
  • Admin config changes propagate within 60 s (poll) or via Socket.IO.

4.3.1  SELECTIVE BLUR (Blur sensitive content = ON)

  Before each upload, Electron reads the foreground window (active-win) and
  matches process name + window title against electron/sensitive-apps.js.

  BLURRED (full Gaussian blur — text not readable):
    Messaging:  WhatsApp, Telegram, Signal, Messenger, Viber, WeChat, …
    Email:      Gmail, Outlook, Yahoo Mail, ProtonMail, Thunderbird, …
    Browser mail tabs: titles containing Inbox/Gmail/Outlook in Chrome, Edge, …
    Social:     Facebook, Instagram, Twitter/X (personal use)

  NORMAL (sharp capture):
    CMS Desktop, IDE, Jira, Figma, work Slack/Teams, spreadsheets, etc.
    Anything not matching the sensitive list.

  If foreground window cannot be detected (permissions), capture stays normal.
  Toggle off in Settings → Monitoring to disable selective blur entirely.
  List is code-defined in electron/sensitive-apps.js — extend for your org.

4.4  CLOCK OUT (manual)

  • Click the red elapsed-timer button in the navbar.
  • Renderer stops Electron scheduler immediately (before API call).
  • POST /api/work-sessions/clock-out   body: { stopReason: "clock_out" }
  • Main process receives sessionId=0 via IPC → stops heartbeat + network monitor.

4.5  LOGOUT WHILE CLOCKED IN

  • AuthContext.logout() clocks out BEFORE clearing tokens (stopReason: logout).
  • Electron scheduler + session monitoring stopped in the same step.
  • If clock-out API fails (network down), heartbeat stale job closes session
    within 3 min; 24 h job is the final fallback.

4.6  SESSION RECOVERY AFTER APP RESTART

  • App opens → GET /api/work-sessions/active.
  • If active session found → sessionId sent to main → heartbeat resumes.
  • Screenshots resume only if monitoring enabled + consent current.
  • After auto clock-out (sleep/shutdown/network), session is ended server-side;
    user must clock in again — no silent resume of stale sessions.

4.7  AUTO CLOCK-OUT (employee-visible)

  The employee sees a toast when main process ends their session:

    system_sleep      "Work session ended — PC went to sleep."
    system_shutdown   "Work session ended — PC is shutting down."
    network_lost      "Work session ended — no network for 2+ minutes."
    app_quit          "Work session ended — app closed."

  After any auto clock-out, the Clock In button returns to green. Employee
  must clock in again when ready to work.

SECTION 5 — ELECTRON LIFECYCLE
────────────────────────────────────────────────────────────────────────────────

5.1  WINDOW CLOSE (✕) AND QUIT

  • Closing the window (✕) triggers initiateGracefulQuit() — clocks out
    then quits the app. Does NOT minimize to tray.
  • Tray → Quit does the same graceful-quit sequence.
  • Auto-update "Restart to update" also triggers graceful quit.

  UX note: the tray icon is only visible while the app is running. There is
  no "hidden in tray but still clocked in" state after closing the window.

5.2  GRACEFUL QUIT SEQUENCE (main-process owned)

  1. User closes window, tray Quit, or before-quit fires.
  2. initiateGracefulQuit() — guarded by quitInProgress promise (no double-exec).
  3. Screenshot scheduler + heartbeat + network monitor stop immediately.
  4. If currentSessionId > 0 → clockOutFromMain("app_quit") — direct API
     call from main process (5 s timeout); does NOT wait for renderer IPC.
  5. cms:session-ended sent to renderer (updates UI if window still alive).
  6. isQuitReady = true → app.quit().

  Legacy IPC (cms:pre-quit / cms:clock-out-done) remains in preload for
  backward compatibility but is no longer the primary quit path.

5.3  POWER EVENTS (sleep / shutdown / restart)

  powerMonitor.on('suspend')   → clockOutFromMain('system_sleep')
  powerMonitor.on('shutdown')  → clockOutFromMain('system_shutdown')
                                 (Windows and Linux)

  Best-effort: OS may kill the process before fetch completes. Tier 2
  heartbeat job (client_disconnected within 3 min) is the fallback.

5.4  TASK MANAGER / FORCE KILL / CRASH

  No JavaScript runs. Electron cannot clock out.
  Backend heartbeat stale job closes session within 3 minutes with
  stopReason = "client_disconnected".

5.5  NETWORK DISCONNECT

  Main process tracks lastSuccessfulApiAt (updated on heartbeat success,
  screenshot upload success, or successful clock-out).
  Every 30 s: if no API contact for 2+ minutes while clocked in →
  clockOutFromMain('network_lost'). Clock-out API may also fail offline;
  Tier 2 heartbeat job closes the server-side session within 3 min.

5.6  SINGLE-INSTANCE LOCK

  Double-clicking the icon when already running: second instance exits,
  first instance window is brought to foreground.

5.7  AUTO UPDATER

  Packaged builds check GitHub Releases on startup. "Restart to update"
  calls quitAndInstall() → graceful quit → install.

5.8  PLATFORM SUPPORT

  Windows   NSIS installer (.exe)
  macOS     DMG with hardened runtime + screen-capture entitlement
  Linux     AppImage and .deb (x64)

SECTION 6 — SECURITY MODEL
────────────────────────────────────────────────────────────────────────────────

6.1  SCREENSHOT URL PROTECTION

  • Screenshots uploaded with ACL: "private" (S3) or local /uploads/.
  • API never returns raw storage URL — always authenticated proxy:
      GET /api/screenshots/:id/content?token=<bearer-token>
  • Proxy verifies auth + ownership on every request; streams from S3/disk.
  • Cache-Control: private, max-age=3600.

6.2  FILE TYPE VALIDATION

  PNG: bytes 0–3 = 0x89 0x50 0x4E 0x47
  JPEG: bytes 0–2 = 0xFF 0xD8 0xFF
  Other payloads → HTTP 400.

6.3  RATE LIMITING

  Clock-in:          5 req/min per user
  Screenshot upload: 60 req/min per user
  Keys based on authenticated user ID (not IP).

6.4  STOP_REASON WHITELIST

  Clients (renderer + Electron main) may submit:
    clock_out, app_quit, logout,
    system_sleep, system_shutdown, network_lost

  Server-only (rejected if submitted by client):
    session_expired, admin_terminated, client_disconnected

6.5  TRUST PROXY

  app.set("trust proxy", 1) — accurate req.ip behind reverse proxy.

6.6  UPLOAD OWNERSHIP

  sessionId on screenshot upload verified against workSessionsTable.

6.7  ADMIN-ONLY DELETIONS

  DELETE /api/screenshots/:id and bulk-delete — admin | super_admin only.

6.8  AUTHENTICATION CACHE

  requireAuth: 30 s TTL user cache; evictUserFromAuthCache() on admin
  deactivation or role change for immediate effect.

6.9  HEARTBEAT AS LIVENESS PROOF

  Heartbeat requires valid Bearer token and monitorable staff role.
  Cannot be used to keep a session alive without an authenticated client.
  Stale heartbeats trigger server-side closure — prevents ghost attendance.

SECTION 8 — EDGE CASE BEHAVIOUR
────────────────────────────────────────────────────────────────────────────────

  Scenario                             Behaviour
  ──────────────────────────────────────────────────────────────────────────────
  Clock In clicked twice rapidly       isClockingInRef guard + MongoDB unique
                                       partial index on active sessions.

  Page refresh while clocked in        Active session restored; heartbeat +
                                       screenshots restart via IPC sync.

  Window ✕ or tray Quit                Graceful quit: main-process clock-out
                                       (app_quit) then app exits.

  PC sleep / hibernate                 system_sleep clock-out; must re-clock-in
                                       on wake. Tier 2 fallback if API fails.

  PC shutdown / restart                system_shutdown clock-out; Tier 2/3 fallback.

  Task Manager kill / crash            client_disconnected within 3 min (heartbeat
                                       job). No screenshots after kill.

  Network lost 2+ minutes              network_lost clock-out locally; Tier 2
                                       closes server session if API unreachable.

  Network returns after auto clock-out Session already ended; employee clocks in
                                       again manually.

  Monitoring off → on                  Immediate screenshot at t=0, then interval.

  60 s config poll, no session change  No duplicate immediate capture.

  Backend unreachable at clock-in      Toast error; no session created.

  Backend unreachable at clock-out     Toast error (manual); Tier 2 closes within
                                       3 min.

  Token expires while clocked in       Heartbeat gets 401 → local session cleared
                                       (no API clock-out). Tier 2 closes server
                                       session within 3 min.

  Admin revokes access                 401 on next API call; scheduler stops;
                                       heartbeat stale job closes session.

  User never consented                 Heartbeat runs; screenshots do not.

  Blur sensitive content ON +          Full blur applied before upload.
  WhatsApp / Gmail / Telegram          Normal capture for CMS, IDE, etc.
  in foreground

  Blur sensitive content OFF           All screenshots normal (no app detection).

  Consent version changes              Screenshots pause; consent banner returns.
                                       Heartbeat continues while clocked in.

  System idle ≥ 5 min                  Scheduled screenshot skipped; session stays
                                       active; heartbeat continues.

  Multiple monitors                    Primary monitor only (sources[0]).

  Screen capture permission denied     Capture skipped; no crash; session active.

  Admin force-terminates session       Socket session_terminated → immediate stop.
                                       stopReason: admin_terminated.

  Admin stops impersonating            stopImpersonation() clocks out target first.

  Client submits internal stopReason   HTTP 400 (session_expired, admin_terminated,
                                       client_disconnected).

  Clock-in without Electron            Web session: no heartbeat, no screenshots.
                                       24 h stale job only fallback.

SECTION 10 — RUNNING THE SYSTEM
